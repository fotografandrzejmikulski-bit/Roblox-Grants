# Roblox Grant Submission Readiness Checklist

## A. Program verification — BLOCKING

- [ ] Current Game Fund application URL or official submission route verified.
- [ ] Current deadline verified, or written confirmation that submissions are ongoing.
- [ ] Current funding range verified.
- [ ] Current eligibility of individual/private applicants verified.
- [ ] Current eligible jurisdictions verified.
- [ ] Current allowable-cost rules verified.
- [ ] Current milestone / payment mechanism verified.
- [ ] Current application fields verified.
- [ ] Current Roblox contact / POC verified through official source.

## B. Applicant verification — BLOCKING

- [ ] Full legal applicant name confirmed.
- [ ] Age requirement met and documented where required.
- [ ] Identity / account verification requirements completed.
- [ ] Roblox account in good standing.
- [ ] Contact information checked.
- [ ] Portfolio links checked.
- [ ] Professional credentials documented.
- [ ] Team members confirmed.
- [ ] Team roles and availability documented.

## C. Product package — BLOCKING

- [ ] One-sentence pitch finalized.
- [ ] Executive summary finalized.
- [ ] Game design overview finalized.
- [ ] Core loop documented.
- [ ] Player journey documented.
- [ ] Social mechanics documented.
- [ ] Avatar identity strategy documented.
- [ ] Technical architecture finalized.
- [ ] AI architecture and safety controls documented.
- [ ] Vertical-slice specification finalized.
- [ ] Performance targets defined by device tier.

## D. Prototype evidence — BLOCKING for a high-confidence submission

- [ ] Playable prototype or compelling interactive proof exists.
- [ ] Multiplayer session demonstrated.
- [ ] Director AI behavior demonstrated.
- [ ] Deterministic fallback demonstrated.
- [ ] Mobile performance benchmark produced.
- [ ] Avatar identity presentation demonstrated.
- [ ] Recorded gameplay walkthrough produced.
- [ ] Key claims have screenshots/video/build evidence.

## E. Financial package — BLOCKING

- [ ] Bottom-up budget reconciles.
- [ ] USD and PLN figures reconcile.
- [ ] FX assumption documented.
- [ ] Monthly cash flow prepared.
- [ ] Hiring/contract assumptions documented.
- [ ] Contractor cost quotations or benchmark evidence available.
- [ ] Hardware/software costs sourced.
- [ ] Legal/accounting costs validated.
- [ ] Marketing spend has measurable objectives.
- [ ] Contingency is explicit.
- [ ] No unsupported historical Roblox fee is included as a required expense.

## F. Compliance and safety — BLOCKING

- [ ] Current Maturity & Compliance requirements verified.
- [ ] Intended audience mapped to current Roblox age categories.
- [ ] AI features mapped to current Roblox policy.
- [ ] Player-facing generated content reviewed.
- [ ] Data minimization policy documented.
- [ ] Telemetry and retention documented.
- [ ] Moderation plan documented.
- [ ] Abuse / exploit response documented.
- [ ] IP licenses / assignments documented.
- [ ] Tax and contracting review completed.

## G. Pitch deck — BLOCKING

Recommended 12–14 slide structure:

1. Title / vision
2. The opportunity
3. The player problem / unmet experience
4. Aetheria in one sentence
5. Core loop
6. What makes it different
7. Director AI
8. Visual / technical ambition
9. Multiplayer + social + avatar identity
10. Production plan
11. Team
12. KPI / go-to-market plan
13. Budget + milestones
14. Ask / next step

## H. Final fact-check

- [ ] Every current-platform factual claim has a primary-source citation.
- [ ] Historical Game Fund information is labeled historical.
- [ ] Experimental Roblox technologies are clearly marked as conditional.
- [ ] No fabricated partnerships, approvals, funding ceilings, fees, or guarantees remain.
- [ ] No unsupported claim says the project will definitely receive a specific award amount.
- [ ] All references resolve to current or appropriately historical primary sources.

## Final submission gate

**GREEN:** all BLOCKING items complete, prototype evidence exists, current Game Fund route confirmed, and all current-policy claims verified.

**AMBER:** narrative and package are strong but one or more current-program or evidence items remain unresolved.

**RED:** application route/eligibility is not confirmed, or major technical/platform claims cannot be substantiated.
